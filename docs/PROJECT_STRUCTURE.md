# Project Structure

This document describes the structure of the Bank Marketing EDA project.

```
AI-FinalProject-MHM-POWER/
│
├── config/                 # Configuration files
│   └── config.yaml        # Main configuration file
│
├── data/                   # Data directory
│   ├── raw/               # Raw, immutable data (gitignored)
│   │   └── bank/          # Bank marketing dataset
│   ├── external/          # External data sources (gitignored)
│   └── processed/         # Processed data (gitignored)
│
├── docs/                   # Documentation
│   └── PROJECT_STRUCTURE.md
│
├── models/                 # Trained models (gitignored)
│
├── notebooks/              # Jupyter notebooks for exploration
│   └── 01_exploratory_data_analysis.ipynb
│
├── reports/                # Generated reports and figures
│   └── figures/           # Visualization outputs (PNG files)
│
├── src/                    # Source code
│   ├── __init__.py
│   └── eda/               # EDA module
│       ├── __init__.py
│       ├── data_loader.py    # Data loading utilities
│       ├── visualizations.py # Plotting functions
│       └── main.py           # Main EDA script
│
├── tests/                  # Unit tests
│   ├── __init__.py
│   └── test_data_loader.py
│
├── .gitignore             # Git ignore rules
├── Makefile               # Common commands (make install, make run, etc.)
├── QUICKSTART.md           # Quick start guide
├── README.md              # Project documentation
├── requirements.txt       # Python dependencies
├── setup.py              # Package setup
├── pyproject.toml        # Modern Python project config
└── run_eda.py            # Entry point script
```

## Directory Descriptions

### `config/`
Contains configuration files in YAML format. This allows easy modification of paths, parameters, and settings without changing code.

**Files:**
- `config.yaml` - Main configuration file with data paths, EDA settings, and plotting options

### `data/`
Data directory organized by processing stage:
- **`raw/`**: Original, immutable data files. Never modify these files.
  - `bank/` - Contains the bank marketing dataset files
- **`external/`**: Data from external sources.
- **`processed/`**: Intermediate data files created during processing.

### `src/`
Source code organized into modules:
- **`eda/`**: Exploratory Data Analysis module with reusable functions.
  - `data_loader.py` - Functions for loading and inspecting data
  - `visualizations.py` - All plotting and visualization functions
  - `main.py` - Main orchestration script that runs the complete EDA

### `notebooks/`
Jupyter notebooks for interactive data exploration and experimentation.
- `01_exploratory_data_analysis.ipynb` - Template notebook for interactive analysis

### `reports/`
Generated outputs:
- **`figures/`**: All visualization files (PNG format) generated by the EDA script

### `models/`
Trained model files (saved after model development). Currently empty, ready for future model artifacts.

### `tests/`
Unit tests for ensuring code quality and correctness.
- `test_data_loader.py` - Example tests for data loading functions

## Root Files

### Essential Files
- **`run_eda.py`** - Main entry point. Run this to execute the complete EDA analysis.
- **`requirements.txt`** - Python package dependencies
- **`setup.py`** - Package installation configuration
- **`pyproject.toml`** - Modern Python project configuration

### Documentation
- **`README.md`** - Comprehensive project documentation
- **`QUICKSTART.md`** - Quick reference guide for getting started
- **`docs/PROJECT_STRUCTURE.md`** - This file

### Development Tools
- **`Makefile`** - Common commands (install, run, test, clean)
- **`.gitignore`** - Git ignore rules for data, models, and generated files

## Best Practices

1. **Never commit data files**: Raw data is gitignored to keep the repository lightweight.
2. **Use configuration files**: Avoid hardcoding paths and parameters. Use `config/config.yaml`.
3. **Modular code**: Keep functions focused and reusable in `src/eda/`.
4. **Documentation**: Update this file when structure changes.
5. **Testing**: Add tests in `tests/` for new functionality.
6. **Outputs**: All generated figures go to `reports/figures/`.
7. **Notebooks**: Use `notebooks/` for interactive exploration and experimentation.

## Quick Commands

```bash
# Run EDA
python run_eda.py

# Or use Makefile
make run        # Run EDA
make install    # Install dependencies
make test       # Run tests
make clean      # Clean generated files
```

## File Organization Principles

- **Separation of Concerns**: Code, data, config, and outputs are clearly separated
- **Modularity**: Functions are organized into logical modules
- **Configuration-Driven**: Settings are externalized to YAML files
- **Industry Standard**: Follows Data Science project best practices
